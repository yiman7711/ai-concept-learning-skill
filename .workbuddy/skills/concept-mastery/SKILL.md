# concept-mastery · 概念精讲

把"学一个新概念"这件事，从"读一段 AI 说的话"升级为"搭建一套结构化认知"。任何陌生概念输入后，本 Skill 会驱动你产出一份**可复用、可核查、可自测**的学习资料，而不是一次性闲聊。

## 适用场景

- 刚接触某个新概念（如 Agent、大模型上下文、Skill、RAG、向量数据库、提示工程……），需要系统入门。
- 为课程作业、面试准备或项目实践建立概念笔记。
- 需要辨析两个相似概念（如 Token 与 Context、RAG 与微调）时提供辨析框架。
- 在 WorkBuddy 中发起"用我的概念学习方法，学一下 XXX"之类请求。

## 输入信息

调用本 Skill 时，需要提供（缺省时按括号内默认处理）：

1. **概念名称**（必填）：要学习的概念，如 `Agent`。
2. **领域/背景**（选填）：概念所属学科或应用语境，默认判断为 AI / 大数据。
3. **学习深度**（选填）：`入门` / `进阶`，默认 `入门`。
4. **输出格式**（选填）：`Markdown`（默认）或 `HTML`。若后续要转成网页在浏览器预览，选 HTML 并沿用统一的深色/浅色主题变量。

## 生成步骤

按以下顺序执行，每一步产出的内容都会进入最终文档的对应小节。

1. **定位与拆解**：用一句话说清"这是什么"，并把概念拆成它的边界（是什么 / 不是什么）。
2. **设定学习目标**：写出 3 条"学完我应该能……"的可检验目标（动词开头，可测量）。
3. **提出核心问题**：列出 3–5 个驱动理解的「核心问题」，后续解释内容要能正面回答它们。
4. **结构化解释**：
   - 个人化理解（不要整段照搬，用自己的话重述）；
   - 核心机制或组成（分点 / 表格）；
   - 关键术语给出中英文对照。
5. **给出一个具体应用场景**：用带步骤的示例说明它在真实任务中怎么用。
6. **概念辨析**：列出 1–2 个最容易混淆的概念 / 使用边界，用「对比维度」表格区分。
7. **设计自测问题**：3–5 道客观题 + 参考答案（可放文末折叠或单独小节）。
8. **整理参考来源**：收集 2–4 个**可核查**的链接（官方文档、权威教程、论文/规范），逐条核实后列出。

## 输出结构

产出的学习资料统一按下面标题组织（Markdown 用 `#`，HTML 转成对应语义化标题）：

```
# <概念名> 精讲（个人学习卡片）

## 0. 一句话定位
## 1. 学习目标
## 2. 核心问题
## 3. 结构化解释
   3.1 我的理解 / 3.2 核心机制与组成 / 3.3 关键术语
## 4. 应用场景示例
## 5. 概念辨析与使用边界
## 6. 自测问题与参考答案
## 7. 参考来源（可核查）
```

> 命名建议：文件存入仓库的 `learning-materials/` 目录，命名清晰，如 `agent.md`、`llm-context.md`、`skill.md`。若同一批要生成概念之间的关系说明，另建 `concept-relationship.md`。

## 资料来源要求（务必遵守）

- **不伪造来源**：每一个参考链接都要确实存在、可打开、内容与该概念对应。拿不准的宁可不放，也不要编一个看起来合理的 URL。
- **优先权威来源**：官方文档 > 官方博客 > 知名教程/论文 > 二手博客。
- **逐条核实**：生成链接后，尽量通过网页检索/访问确认标题与内容吻合；无法在线核实的，在文档里注明"待核实"。
- **解释不得整段照搬**：AI 生成的解释要经本人重写、用自己的语言和例子表达，体现个人理解，而非复制粘贴 AI 输出。
- 注明学习日期与作者（本人）。

## 自检要求（产出后逐条核对）

完成资料后，对照以下清单自检，全部通过才算完成：

- [ ] 顶部有 YAML 元数据（若为 Skill 相关文件）或清晰的标题/日期（学习资料）。
- [ ] 学习目标写的是"我能……"且可检验，不是笼统的"了解 X"。
- [ ] 结构化解释包含"我的理解"，不是整段照搬 AI 文本。
- [ ] 应用场景是可运行的步骤示例，不是泛泛而谈。
- [ ] 概念辨析用表格对比，能回答"它与 X 有何区别"。
- [ ] 自测问题给出参考答案。
- [ ] 每个参考来源都是真实可核查的链接，无编造。
- [ ] 内容里没有机密信息（无 API Key / 密码 / 隐私）。
- [ ] 个人确认通读一遍、能用自己的话讲给同学听。

## 说明

- 本 Skill 只负责"组织与生成学习材料"的流程，**知识准确性最终以资料中的可核查来源和个人理解为准**。
- 支持一次输入一个概念输出一份资料；如需多个概念，可多次调用或先产出各自资料再写关系说明。
