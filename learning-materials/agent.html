Agent（智能体）精讲

0. 一句话定位

Agent 不是某个模型，而是以 LLM 为"大脑"、能自主规划、调用工具、在真实环境中行动并根据结果自我纠偏，最终代表用户完成目标任务的一整套闭环系统。

3. 结构化解释

3.1 我的理解

一开始我很容易把"GPT 很聪明"当成"这就是 Agent"。后来才明白：一个只会单轮问答的模型，就像一位只有大脑、没有手脚、也不能翻书的专家——它只能"说"，不能"做"。Agent 给这个大脑配上了手（工具）和一套工作方法（循环）：它能自己决定先查什么资料、再调用哪个 API、拿到结果后判断下一步，甚至发现方向错了主动改。

用一句话记住："模型负责想，工具负责做，Agent 把"想+做+看结果"串成了一个能自动推进的闭环"。让我印象最深的是，它的执行路径不是开发者预先写死的，而是模型根据当前情况动态决定的——这正是它和传统自动化最根本的分水岭。

3.2 核心机制与组成

不同框架的表述略有差异，但骨架一致。OpenAI 官方把 Agent 的基石概括为三件事：

组成英文作用我的理解
模型Model负责推理与决策的 LLM"大脑"，决定下一步做什么
工具Tools可调用的外部函数 / API"手脚"，去搜索、查库、写文件、调用系统
指令Instructions行为准则与护栏（guardrails）"性格与边界"，规定该怎么干活、什么不能做

Anthropic 更强调运行方式，把 Agentic System 分成两类，这是最容易混淆的点：

类型控制权路径何时用
工作流 Workflow由预定义代码控制固定、可预测任务清晰、步骤可预先拆解
Agent由 LLM 动态自主控制灵活、开放任务开放、需要动态决策与纠错

一个典型 Agent 的工作方式是"思考 → 行动 → 观察"循环（ReAct 思想的体现）：

模型思考(Reason) → 调用工具(Act) → 看结果(Observe) → 再思考 → …… → 判断"目标达成"→ 结束并交还控制权

3.3 关键术语（中英对照）

  • Agent / 智能体：代表用户独立完成任务的自主体系统。
  • Model / 模型：Agent 背后的大语言模型。
  • Tool use / Function calling / 工具调用：模型按格式请求调用外部函数的能力。
  • Instructions / 指令、System prompt / 系统提示：规定 Agent 行为准则。
  • Workflow / 工作流：用预定义代码路径编排 LLM 与工具的系统。
  • Handoff / 任务转移：多 Agent 之间把任务交给更合适的子 Agent。
  • Guardrail / 护栏：限制 Agent 行为的输入/输出安全机制。

4. 应用场景示例

场景让 Agent 自动做"竞品价格调研日报"

假设我要让 Agent 每天早上把某几款产品的公开价格整理成一张表。任务没有被写成固定脚本，因为页面结构会变、要判断的信息很模糊：

  1. 建 Agent：给它指令"每天去这几个公开页面找产品 A/B/C 的价格，整理成统一表格，拿不准的标注出来"，并授予"网页搜索""读取/写表格文件"两个工具。
  2. 循环执行：模型先调用网页搜索抓取 → 观察页面 → 发现某款信息不全 → 再换关键词补查 → 判断够了 → 写入表格 → 汇报完成。
  3. 异常处理：若某数据源完全打不开，Agent 可停下来把问题交还给我，而不是硬编一个"失败就重试三次"的死逻辑。

这正是 Agent 的用武之地：判断模糊、需要查漏补缺、路径不固定。若只是"每周把同一份 CSV 转格式"，一个几行的确定性脚本就够，根本不必上 Agent。

5. 概念辨析与使用边界

对比维度Agent易混淆对象
vs. 单轮 LLM / 聊天机器人能调用工具、多步执行、自我纠错只"说"不"做"，不控制工作流执行
vs. Workflow（工作流）模型动态决定路径开发者写死代码路径，模型只填步骤
vs. 单纯"工具"Tools是系统/编排层，会主动调度工具是被调用的原子能力，本身不决策

使用边界提醒：Anthropic 明确建议——"先找最简单的方案，只在复杂度能带来可衡量收益时才引入 Agent。"任务规则明确、步骤固定时，一个确定性工作流反而更快、更省钱、更好排查。不要为了"显得智能"而滥用 Agent。

6. 自测问题

Q1：单个 GPT 模型算不算一个 Agent？为什么？

参考答案：通常不算。缺少"调用工具 / 与环境交互 / 多步自主决策"的闭环。若把它包进能调工具并按模型决策推进的系统中，才构成 Agent。OpenAI 明确把"简单聊天机器人、单轮 LLM"排除在 Agent 之外。

Q2：Agent 三大核心组成是哪三个？

参考答案：模型（决策/推理）、工具（行动）、指令（行为准则与护栏）。

Q3：Agent 与 Workflow 最本质的区别是什么？

参考答案：控制权归属。Workflow 的执行路径由预定义代码决定；Agent 的执行路径由 LLM 根据当前上下文动态决定，能自我纠错。

Q4：什么信号说明"你其实不该建 Agent"？

参考答案：任务步骤明确、可预先拆解成固定规则；此时确定性工作流更可预测、更便宜、易排查。Agent 适合规则难维护、判断模糊、重度依赖非结构化/开放决策的场景。
